EEL5764 Group 4 -- Workloads for the systolic-array scaling study
==================================================================

This folder is the single source of truth for the four workloads in the
proposal (Sec. IV.C).  One script writes every operand and golden result,
in the format each simulator needs, from one fixed seed.  gem5 uses them
now; the RTL testbenches will use the same data later.


1. Files
--------

  workloads.yaml     Shapes, layer descriptions and citations.  Edit this,
                     not the script, to change or add a workload.
  gen_workloads.py   Generator (numpy + PyYAML).  Reads workloads.yaml,
                     writes out/.  Fixed seed, so the output is identical
                     every time.
  out/               GENERATED by make workloads.  Not in git (see
                     ../.gitignore).
    workloads.json   Index of everything generated (shapes, file hashes).
    gem5/<name>/          Full-size layer, for gem5 phase-1 runs.
    gem5/<name>_rtl/      Reduced layer (same M, K and N_out capped at 96),
                          for gem5 <-> RTL cross-validation.
    rtl/<name>_rtl/       The same reduced layer as $readmemh hex, for
                          Questa.

  gem5/<name>/ contains:
    A.bin          INT8,  row-major  M x K        (activations)
    W.bin          INT8,  row-major  K x N_out    (weights)
    C_golden.bin   INT32 little-endian, row-major M x N_out, = A . W
    meta.json      shape, file layout, sha256 of each file, layer, source

  rtl/<name>_rtl/ contains:
    A.hex, W.hex   one 8-bit two's-complement value per line (2 hex digits)
    C_golden.hex   one 32-bit two's-complement value per line (8 hex digits)
    shape.svh      localparams WL_M, WL_K, WL_N_OUT to `include in a TB
    Each hex file starts with a // comment line, which $readmemh skips.
    Load with e.g.  $readmemh("A.hex", a_mem);  where a_mem is a flat
    logic [7:0] array of M*K entries (row-major, index m*K + k).

  The gem5 model (../gem5_model/) reads only meta.json + the three .bin
  files.  It does the tiling and zero padding for N itself, so the same
  files serve N = 8, 16, 24 and 32.


2. Generate
-----------

  make workloads                                 # everything (~40 MB)

  or, from the repository root (any Python with numpy and PyYAML):

  python3 workloads/gen_workloads.py                       # everything
  python3 workloads/gen_workloads.py --only bert_attn_qk   # one workload
  python3 workloads/gen_workloads.py --no-full             # reduced only

  out/workloads.json records the sha256 of every file, so two machines can
  check that they generated identical data.

  The script checks itself.  For the ResNet layer it builds the im2col
  matrix and checks that A . W equals a direct (loop-over-kernel)
  convolution of the same tensors before writing anything.  The gem5
  model then checks its simulated output against both a reference GEMM
  and C_golden.bin, so a bad file shows up as a verify FAIL.


3. The workloads and where they come from
-----------------------------------------

Every workload is one INT8 GEMM with INT32 accumulation,

    C[M x N_out] = A[M x K] . W[K x N_out]

where M, the number of activation rows streamed through each N x N weight
tile, is the reuse term of eq. (1).  The shapes span that reuse, from
M = 784 down to M = 1.

  name              class          M      K      N_out   MACs
  ---------------   -------------  -----  -----  -----   ---------
  resnet50_conv3x   compute-bound    784   1152    128   115.6 M
  bert_ffn1         compute-bound    128    768   3072   302.0 M
  bert_attn_qk      intermediate     128     64    128     1.0 M
  llama7b_gemv      memory-bound       1   4096   4096    16.8 M

3.1 resnet50_conv3x -- ResNet-50 conv3_x 3x3 convolution via im2col

  Source: K. He, X. Zhang, S. Ren, J. Sun, "Deep Residual Learning for
  Image Recognition," Proc. IEEE CVPR, 2016, pp. 770-778.
  arXiv:1512.03385.  Table 1, "50-layer" column, row conv3_x:
  output 28x28, block = [1x1, 128; 3x3, 128; 1x1, 512] x 4.

  Chosen layer: the 3x3, 128-filter convolution inside a conv3_x
  bottleneck block that is NOT the first block of the stage (blocks 2-4).
  Why not block 1: the Table 1 caption says downsampling is done by
  conv3_1 with stride 2.  Implementations differ on where that stride
  goes.  The original puts it on the first 1x1 conv; torchvision's
  "ResNet v1.5" puts it on the 3x3 conv, which then sees a 56x56 input.
  Blocks 2-4 have no stride under either convention: the 3x3 conv reads
  a 28x28x128 tensor (stride 1, pad 1) and writes 28x28x128.

  Lowering to GEMM (im2col):
    M     = output pixels         = 28 * 28       = 784
    K     = kernel window * C_in  = 3 * 3 * 128   = 1152
    N_out = C_out                                  = 128
  Row p of A is the 3x3x128 input window under output pixel p, flattened
  in (r, s, c_in) order, with zeros where the window hangs over the pad.
  W is the filter tensor [R][S][C_in][C_out] reshaped to 1152 x 128.
  im2col references:
    K. Chellapilla, S. Puri, P. Simard, "High Performance Convolutional
    Neural Networks for Document Processing," 10th Int. Workshop on
    Frontiers in Handwriting Recognition (IWFHR), 2006.
    S. Chetlur et al., "cuDNN: Efficient Primitives for Deep Learning,"
    arXiv:1410.0759, 2014 (Sec. 3, lowering convolution to GEMM).
  Data: input activations are drawn from [0, 127], as they would be after
  the preceding ReLU, so they still fit the signed INT8 datapath.  Filters
  are drawn from the full INT8 range.

3.2 bert_ffn1 -- BERT-base feed-forward, first linear layer

  Source: J. Devlin, M.-W. Chang, K. Lee, K. Toutanova, "BERT: Pre-training
  of Deep Bidirectional Transformers for Language Understanding," Proc.
  NAACL-HLT, 2019, pp. 4171-4186.  arXiv:1810.04805.
    Sec. 3 "Model Architecture": BERT-BASE has L=12, H=768, A=12, and the
    feed-forward/filter size is 4H = 3072.
    Appendix A.2: 90% of pre-training steps use sequence length 128.
  GEMM: X[128 tokens x 768] . W1[768 x 3072]  ->  M=128, K=768, N_out=3072.
  This is the H -> 4H expansion.  The 4H -> H projection (M=128, K=3072,
  N_out=768) has the same MAC count and could be added as bert_ffn2.

3.3 bert_attn_qk -- BERT-base attention scores Q . K^T, one head

  Sources: Devlin et al. 2019 (above) for H=768, A=12 heads, seq 128.
  A. Vaswani et al., "Attention Is All You Need," Proc. NeurIPS, 2017,
  Sec. 3.2.1 (scaled dot-product attention, Q K^T) and Sec. 3.2.2
  (d_k = d_model / h, so d_k = 768 / 12 = 64 here).
  GEMM: Q_h[128 x 64] . K_h^T[64 x 128]  ->  M=128, K=64, N_out=128.
  gem5 gets A = Q_h and W = K_h^T, stored as a normal K x N_out matrix.
  Why "intermediate": the reuse per tile is still M=128, but K is only 64,
  so there are very few tiles (2 x 4 = 8 at N=32).  The one-time weight
  prologue and 2N-1 drain are spread over little work, and at N=24 the
  K=64 dimension pads to 72 (11% wasted MACs).  In a full model this GEMM
  also runs once per head (x12) and per layer, with small operands each
  time.

3.4 llama7b_gemv -- LLaMA-7B single-token decode, one projection

  Source: H. Touvron et al., "LLaMA: Open and Efficient Foundation
  Language Models," arXiv:2302.13971, 2023.  Table 2: the 6.7B ("7B")
  model has dimension 4096, 32 heads and 32 layers.
  GEMV: during autoregressive decode with batch 1, each attention
  projection (e.g. W_q, 4096 x 4096) multiplies ONE new token vector:
  x[1 x 4096] . W[4096 x 4096]  ->  M=1, K=4096, N_out=4096.
  With M = 1 every weight byte is used once, so the array is bound by
  reuse (1/N utilization) and by how fast weights stream from DRAM,
  not by the scratchpad.  This matches proposal Sec. II.B.
  The 16 MiB weight matrix is far larger than any on-chip scratchpad, so
  in gem5 the weights come from DDR4 through the DMA engine.

3.5 Reduced (_rtl) variants

  For RTL simulation (Questa) and for checking gem5 against the RTL, each
  workload also comes in a smaller version.  It keeps M, which is what sets
  reuse and the utilization behaviour, and takes the first
  min(K, 96) columns of A and the matching min(K, 96) x min(N_out, 96)
  block of W.  96 = lcm(8, 16, 24, 32), so a reduced layer is never padded
  for any swept N unless the original dimension is smaller than 96.

    resnet50_conv3x_rtl   784 x 96 x 96
    bert_ffn1_rtl         128 x 96 x 96
    bert_attn_qk_rtl      128 x 64 x 96
    llama7b_gemv_rtl        1 x 96 x 96

  The golden output of a reduced layer is recomputed from the sliced
  operands (it is a sub-GEMM of the real layer, not a slice of its output).


4. Notes and assumptions
------------------------

  * The data is random, not trained weights.  The timing of a
    weight-stationary array does not depend on the values; the values only
    let the simulators prove their datapath is correct.  Seed: 5764
    (workloads.yaml), with a per-workload sub-seed so --only regenerates
    identical files.
  * INT32 accumulation never overflows for these shapes
    (|a*w| <= 2^14, K <= 4096, so |C| < 2^26).
  * Verify every shape against the cited paper before the results freeze.
    I checked the numbers above against the papers' architecture tables,
    but the page and section numbers should be confirmed when writing the
    bibliography.
  * Add these to the paper's references: He 2016, Devlin 2019, Vaswani
    2017, Touvron 2023, and Chetlur 2014 (im2col).  gem5 itself should be
    cited as J. Lowe-Power et al., "The gem5 Simulator: Version 20.0+,"
    arXiv:2007.03152, 2020.
